# 当前轮次细则设计

日期：2026-11-26  
状态：已确认（2026-11-26）

## 意图

在现有 TPS 弹层的左上角增加第三个页签「本轮细则」，用一张紧凑的信息卡展示**当前轮次**的生成速度、响应耗时、token 用量与输出比例。

参考图最有价值的部分是把速度与耗时拆开：流式 / 端到端、TTFT / 生成 / 总计。本设计借鉴这个信息结构，但不照搬参考图的全部字段，也不引入会话级统计。

## 目标

- 当前轮次正在进行时，能看到实时流式速度、端到端估算速度与已产出的估算 token。
- 当前轮次结束后，能看到基于宿主真实 `usage` / `timing` 的精确汇总。
- 三个页签继续保持相同的外框宽度与最小高度，切换时布局不跳。
- 所有数字口径在 `?` 说明里可查，缺失数据时显示 `—`，不编造。

## 非目标

- 不做会话总计：轮数、工具调用次数、全轮次平均缓存率。
- 不做上下文窗口上限（例如 `449k / 512k`）；当前插件没有这个数据源。
- 不改变现有胶囊的实时速度算法，也不改变「每步平均」表的口径。
- 不引入新的网络请求、宿主服务或跨插件 DOM 读取。
- 不把运行中步骤的字符估算冒充成真实 token 账单。

## 约束

- 继续使用现有 `legacy.nodes` 与 `legacy.partial`，不新增宿主 API。
- 运行中的 token 仍按现有系数估算：CJK 1 字/token，其它 4.2 字符/token。
- 速度沿用用户已确定的整数显示；缓存率保留两位小数。
- 复用现有主题 token、面板定位、矮窗口滚动、sticky 表头与焦点管理。
- `legacy.nodes` 若因分页缺少当前轮次最早步骤，则总耗时与端到端速度显示 `—`，不能用不完整的起点硬算。检测规则：当前轮次观测到的最小 `step > 1` 时视为缺头；步号从 1 开始时才认为汇总完整。

## 方案

### A. 第三个页签「本轮细则」（采用）

在现有「实时速度 / 每步平均」后增加「本轮细则」。页签、状态仓库、面板头部都沿用现有结构。

优点：

- 与参考图的独立信息卡最接近；
- 不把主面板塞成图表 + 表格 + 明细三块同时显示；
- 复用现有页签状态、焦点、Esc、定位与滚动逻辑；
- 后续若真要加会话总计，仍有独立位置可放。

代价：`ChartTab`、面板高度计算、头部标签与测试需要扩展。

### B. 在现有两页下面加可折叠明细卡

不改页签，只在内容下方加一块「本轮细则」。

不采用：会破坏「两页同高、档位按钮同底线」的现有布局；展开后面板显著变高，且每次切换页签都要重新处理折叠状态。

### C. 独立小浮层

在 `?` 旁增加第二个入口，打开单独的明细卡。

不采用：多一套浮层状态、定位、焦点与关闭逻辑，却不会比第三个页签更清晰。

## 界面

左上角页签变为：

```text
[实时速度] [每步平均] [本轮细则]              ? ×
```

「本轮细则」内容控制在现有内容区高度内，三个页签共享同一个 `minHeight`：

```text
第 61 轮 · 7 步 · 111.0s

生成速度   流式 239 tok/s  |  端到端 137 tok/s
响应耗时   TTFT 4.96s  ·  生成 6.60s  ·  总计 11.56s
本轮输出   1,234,567 tok          缓存率 99.30%
输出比例   思维链 32%  ▓▓▓▓░░░░░░  正文/工具 68%
```

运行中时在标题旁显示「估算」标记；结算后标记消失。速度取整，秒数保留两位小数，token 使用千分位。

## 数据口径

### 当前轮次与步数

- 当前轮次 = `legacy.partial.turn`、`legacy.nodes` 中有效 assistant 节点最大轮次与 `legacy.turnTimings` 最大轮次中的较大者。
- 步数 = 当前轮次内去重后的 assistant 步骤数，加上尚未出现在 nodes 中的运行中 `partial.step`；步号交错也按“节点是否存在”判断。
- 同一 `turn:step` 的重复或修订节点只计一次，采用最新出现的节点。

### 时间

- `turnStart`：优先取 `legacy.turnTimings` 的 `startTime`；缺失时取当前轮次有效节点中最小的 `stepStartTime`。
- `turnEnd`：优先取 `legacy.turnTimings` 的 `endTime`；轮次仍在运行时取渲染时的 `now`，因此工具执行期间也会持续推进。
- `总计`：`turnEnd − turnStart`。缺头、任一步骤时间缺失、步骤间倒挂/重叠或终点早于起点时不显示。
- `TTFT`：只取当前轮次最早步骤的 `firstTokenTime − stepStartTime`；最早步骤首 token 缺失或倒挂时显示 `—`，不跳到后续步骤。
- `生成`：当前轮次各有效步骤的 `completedTime − firstTokenTime` 之和。工具-only 的零输出步骤不贡献生成耗时；有输出但缺少有效生成时间、已结算步骤缺输出用量，或运行中步骤已有估算输出时，汇总显示 `—`。

### 速度

- 结算后的流式速度 = 当前轮次 `Σ outputTokens ÷ Σ生成毫秒`。
- 结算后的端到端速度 = 当前轮次 `Σ outputTokens ÷ 总计毫秒`，包含首包等待、重试与步骤间工具执行。
- 运行中流式速度直接复用胶囊当前的实时估算读数。
- 运行中端到端速度 = 已结算真实输出 + 当前步骤估算输出，再除以已知的本轮已耗时；本轮起点未知时显示 `—`。

### 用量与比例

- `本轮输出`：已结算节点的 `outputTokens` 之和，加上运行中步骤的现有估算 token。
- `缓存率`：`Σ cacheReadTokens ÷ Σ promptTokens`。提示总量可由 `totalTokens − outputTokens` 确定，或三个 prompt 桶齐全时确定；任一已结算步骤字段不齐或分母矛盾时整体显示 `—`。
- `输出比例`：`Σ reasoningTokens ÷ Σ outputTokens` 为思维链，其余为正文/工具。所有正输出步骤必须同时具备两项且思维链不超过输出；零输出步骤不参与分母，未知输出不能跳过。
- 比例条必须同时显示文字百分比，不能只靠颜色表达。

## 实现边界

- 新增纯聚合模块 `turn-details.ts`，输入 nodes / running / runningTokens / liveSpeed / now / turnTimings，输出展示模型；不碰 React，便于完整单测。
- `SessionStream` 增加当前 nodes 引用、运行中 turn/step 信息与 `turnTimings`，沿用现有 `runningTokens`，不重复计数。
- `ChartTab` 增加 `details`，头部与状态测试同步扩展。
- 明细页打开时每 500ms 重画一次，让运行中的流式读数、端到端估算与耗时继续更新；结算后随 nodes 更新。
- `panel-metrics.ts` 增加明细页高度；明细页与现有两页共享最小外高，定位与滚动逻辑不变。
- `help.ts` 增加「本轮细则」一节，写明上述口径。
- 现有实时速度与每步表格保持行为不变。

## 测试

- 当前轮次选择、步骤去重、运行中步骤合并。
- 多步汇总：流式 / 端到端、TTFT / 生成 / 总计。
- 工具-only 零输出步骤不污染生成耗时。
- 缓存率与思维链比例的聚合、缺失字段与倒挂时间。
- 分页缺少最早步骤时显示 `—`。
- 运行中使用估算、结算后切换为真实用量。
- 第三个页签状态、面板高度、帮助文案与既有测试保持全绿；审查后总测试数为 229 条。

## 验收

- 弹层左上角出现第三个页签，切换不改变外框宽度与最小高度。
- 当前轮次完成后，数字能与同轮 assistant 节点的 `usage` / `timing` 对上。
- 当前轮次运行中，明确标为估算，不出现假的精确感。
- 任一步骤数据缺失时显示 `—`，不显示半真半假的汇总。
- 不出现会话总计或上下文上限字段。
