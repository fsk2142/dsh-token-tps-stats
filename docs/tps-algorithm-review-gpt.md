## 插件目前怎样测速

- 项目是 `dsh-token-tps-stats`，本次分析对应本地源码 `98f90d2`。输入框旁的胶囊显示当前会话的实时 tok/s，面板有实时折线和「每步平均」表格。
- 客户端按会话从 `useChat` 读取 `legacy.partial`。它提供 `turn/step/blocks` 和累计正文、思考文本。插件对累计文本做差分，按现有系数估算 token，CJK 约 1 字/token，其他字符约 4.2 字/token。这个换算只是启发式，代码、中文和不同模型的分词误差可能不同。
- `legacy.nodes` 提供已完成步骤的用量和时间。实时显示测的是 DSH 客户端收到的可见输出速率。每步表格最终使用该步的 `usage.outputTokens`，并优先使用插件观测到的活跃时长，缺失时再用宿主的时间字段。两边的分子和时间范围都可能不同。
- 胶囊目前将最近 9 秒内的估算 token 除以固定 9 秒，再做时间常数 3 秒的一阶平滑。折线用每秒分桶后的 9 秒滑窗，因而两个位置在同一时刻可以显示不同的数字。
- 两处采集问题会直接导致漏显。遇到新步骤时，现有差分逻辑只记首份快照为基线。如果输出都在首份快照里，随后 `partial` 就清空，增量为零。即便收到一次增量，速度计第一次读取也从 0 起步，而胶囊目前要读到正数才启动 100ms 刷新。短步可能因此停在 0。

## 我建议的实现

1. **先修差分与刷新。** 已有可靠的同会话边界时，例如已观察到空闲后开始新步骤，或连续观测到步骤切换，首份快照的可见新增量入账。首次挂载或切入正在运行的会话时，用已有内容建立基线。发现重试清空、文本替换或块重排时重新建立对应基线。若整步在客户端两个快照之间发生、插件只见到结算节点，这一段缺乏实时可见数据。收到正增量就启动刷新，两级状态都低于停表阈值后再停止，防止第一层有值、第二层暂时还为 0 时提前停表。
2. **按真实时间差运行两级指数低通。** 两级时间常数各为 650ms。用同一条估计序列驱动胶囊和折线。胶囊约每 100ms 读一次，折线记录同一估计器的每秒读数。评审时也可比较按秒记录峰值或平均值，检查短步是否会被绘图采样漏掉。折线端点如标「当前」，应取同一时刻的当前读数。
3. **将积压增量按采样区间连续分摊。** 两次可靠采样之间收到 `N` 个估算 token，可以把它视为 `(from, to]` 上的一段均匀输入。用滤波器的解析更新计算贡献。现有实现按 1 秒切片并将每片记到末尾，新滤波器下仍有人工起伏。同毫秒增量先合并。若缺少可信区间或两次时间戳相等，按点输入处理。遇到切会话、挂起或长时间没有采样，应先判断原区间是否仍可信。均匀分摊只能估计区间内的分布。
4. **保持实时口径可解释。** 只将观测到的正文、思考增量送入实时滤波。结算的 `outputTokens` 用在每步表格。要覆盖纯工具参数生成，DSH 宿主需要提供按会话归属、带时间戳的持续增量或累计输出 token 数。当前样本里的工具参数通常在临近完成时才集中出现。

### 计算公式

令时间单位为秒，`u` 是区间内的输入速度，`x`、`y` 是两级滤波状态，输出为 `y`。

```text
dx/dt = (u - x) / τ
dy/dt = (x - y) / τ
τ = 0.650 s

h = (to - from) / τ
a = exp(-h)
u = N / (to - from)

x_new = a*x + (1-a)*u
y_new = a*y + a*h*x + [1-a*(1+h)]*u
```

更新 `y` 时使用更新前的 `x`。空档令 `u = 0`。同毫秒的点输入在该时刻令 `x += N/τ`，`y` 随后连续变化。这等价于对 token 计数应用冲激响应 `K(t) = t*exp(-t/τ)/τ²`，其面积为 1，所以长期稳定输入 100 tok/s 会读到 100 tok/s。解析更新允许用实际经过时间计算，避免依赖定时器是否准时。

对离线回放或迟到的区间增量，可用阶跃响应 `F(t) = 1-(1+t/τ)*exp(-t/τ)`，且 `t <= 0` 时取 0。区间贡献是 `N/(to-from) * [F(now-from)-F(now-to)]`，仅在这批增量已经交付后纳入。实现应防止读取操作推进状态后又把迟到增量按同一段时间重算一遍。一种方式是让读取只做状态外推，采集端独立提交状态。过往已经显示的点是否允许回填，要有明确的产品口径。

## 对比结果

表中速率和 RMSE 均为 tok/s。短步合成场景在 0.1、0.2、0.3 秒各交付 48 个估算 token，分别均匀分配到各自前 100ms，0.5 秒读数。真实短步一列以宿主日志的首个可见片段为零点，将宿主时间线按对齐的 100ms 采样周期合并，再取 0.5 秒读数的中位数。真实短步没有每毫秒的模型生成速率真值。

| 候选 | 合成短步 0.5s ↑ | 16 个真实短步 0.5s 中位数 ↑ | 每秒一包 RMSE ↓ | 每 1.5 秒一包 RMSE ↓ | 20 组不规则到包平均 RMSE ↓ | 稳定 100 停流 3s 后 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 二阶指数 550ms | 85.81 | 57.66 | 11.92 | 24.19 | 20.26 | 2.76 |
| **二阶指数 650ms** | **67.94** | **47.35** | 8.72 | 18.07 | 15.91 | 5.56 |
| 二阶指数 750ms | 54.95 | 39.25 | 6.64 | 13.96 | 12.89 | 9.16 |
| 梯形窗 2.6s | 50.40 | 39.23 | 3.58 | 22.50 | 16.63 | 0 |
| 滑窗 2s + 指数 600ms | 31.40 | 23.47 | 0.32 | 11.32 | 10.58 | 5.46 |

- 梯形权重在 0–0.5s 线性上升，0.5–1.9s 保持，1.9–2.6s 线性下降，按面积归一化。滑窗方案先做固定 2s 均匀滑窗，再串联 600ms 一阶低通。周期模拟以 100 tok/s 恒定生成，每批交付 `100 × 批次间隔秒数` 个 token，按该批前 100ms 分配。不规则场景每次的间隔从 0.3–1.5s 取样。RMSE 从开流后 7.05s 到 28.95s 每 0.1s 对 100 tok/s 计算，20 组的 RMSE 取算术平均。
- 现有生产速度计在上述合成短步里，0.5s 约 **1.84 tok/s**，全程峰值约 **4.41 tok/s**。这一基线直接调用现有速度计，每 100ms 喂入同样的 token 数并读取。候选算法为离线模拟。
- 合成积压场景中，100 tok/s 稳定生成，界面阻塞 6s 后一次交付 600 token。650ms 二阶算法恢复后 1s 内的峰值约 **100 tok/s**（整个 6s 连续分摊）或 **339 tok/s**（全量压入最后 100ms）。同一数据沿用每秒切片时，恢复 300ms 的读数约 **109 tok/s**。当积压期间包含真实的停顿或速度切换时，均匀分摊会掩盖这些变化。
- 暂定 650ms 是因为短步响应优先，同时 650ms 比 550ms 更能压制批量到包的波动。如果显示优先级改为稳态尽量少跳，2s 滑窗加 600ms 在本组不规则模拟里的误差更低。样本来自单会话，尚缺其他会话、模型和 DSH 界面实测。
