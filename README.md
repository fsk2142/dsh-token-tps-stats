# dsh-token-tps-stats

在 DSH 输入框底部那一行显示**当前会话的实时输出速度**（tok/s），排在那两个官方胶囊
（轮次/步数、用量）的左边。**点一下胶囊**，会在它正上方弹出图表，左上角可以切换
**实时速度**（最近 1 / 3 / 5 分钟）与**每步输出**（最近 5 / 10 / 20 步）。

## 它长什么样

```
◷ 实时输出速度（TPS）：42 tok/s   ◷ 93 轮 4047 步 · 148 tok/s   ⛁ 1159M tok · …
```

- 模型在流式输出时数字**持续跳动**（一律整数：小数位来自换算系数的猜测，不是真精度）；
- 速度通过两级各 650ms 的平滑缓升缓降。稳定输出时约 3 秒达到目标的 94%；
- 完全没有动作时**固定在 `0 tok/s`**（不会消失）。

点胶囊会弹出图表（`shell.overlay` 槽位，`position: fixed` 摆在胶囊正上方，
上方放不下就摆到下方）。**左上角两个页签**切换整张图：

```
┌────────────────────────────────────────────────┐
│ [实时速度] [每步平均]                       ? ×│
│ 实时速度 · 最近 1 分钟                         │
│ 当前 42 tok/s · 平均 31 tok/s · 峰值 58 tok/s  │
│ 100 ┤                                          │
│     │        ╭─╮                               │
│  50 ┼───╭───╯ ╰──╮──────────                   │
│     │   ╯         ╰                            │
│   0 ┴──────────────────────────────            │
│   60 秒前                        现在          │
│                   [1 分钟][3 分钟][5 分钟]     │
└────────────────────────────────────────────────┘
```

三个读数**各自带 `tok/s`**（用户 2026-11-13：原来只有「当前」带单位，平均和峰值
是光秃秃的数字，「至少统一一下吧」）。

切到「每步」，**不再画折线**，而是一张表（用户 2026-11-13：「直接列出来第一步，
输出多少，输入多少，命中多少，平均速率多少」）：

```
┌────────────────────────────────────────────────────┐
│ [实时速度] [每步平均]                      [?] [×] │
│ 每步输出 · 最近 5 步                               │
│ 步     读取    输入   输出    命中   速度          │
│ #2.3  364,213   1,204   812   99.87%  47 tok/s     │
│ #2.2  363,530     988   153   99.72%  38 tok/s     │
│ #2.1  363,092     721   640   99.80%  52 tok/s     │
│                      [5 步][10 步][20 步]          │
└────────────────────────────────────────────────────┘
```

表格上方原来那一长行说明（约 446px，**在 416px 的内容宽里会被截断**）已经搬进
右上角的 `?`（用户 2026-11-13：「这个地方不需要这么长的说明吧，可以在右上角的
X 旁边放一个可以点击的？来进行解释说明」）。随后用户又说「这句话不用加」——
所以**一行常驻提示都不留**，标题下面直接是表头。

`?` 和 `×` 都是**方形描边按钮**（22px，与页签、档位按钮同一套边框），用户原话是
「右上角的 X 和 ? 加一个小方框吧，就像和每步平均那个样子」。`?` 点开后在内容流里
展开两节口径说明（内容在 `help.ts`，有单测盯着「五个列名都解释到」）。

**两页的档位按钮落在同一条底线上**（用户 2026-11-13：「一个底部对齐，一个上去了，
建议你两边对齐一下，不然切换的时候整个页面都是跳了一下」）。面板是 flex 列、
页内容 `flex: 1`、按钮行 `marginTop: auto` —— 光把外框撑到等高是不够的，矮的那页
会把按钮留在上方，切页签时按钮行照样跳。

**每个档位按钮统一 50px 宽**（用户：「两边的按钮大小宽度不一样」→「统一为 50px」）。
原来按钮宽度随文案自适应：`1 分钟` 约 49px、`5 步` 约 38px，两组看起来像两种控件。
现在两组都是 3 个 50px + 2 个 6px 间隙 = 162px，整排左右都齐。

列的**顺序与简称**是用户定的：「缓存读取、未缓存输入、输出、缓存命中、平均速度，
但是都用简写：读取 / 输入 / 输出 / 命中 / 速度」。

- **读取** = `cacheReadTokens`；**输入** = `inputTokens`（**未缓存**那部分，
  不是 `total − output` —— 那会把缓存算进来）；**输出** = `outputTokens`；
- **命中** = 读取 ÷（读取 + 输入 + 写入）。**统一保留两位小数**：用户先问「为什么
  命中率都是 100%」（那一行真实是 99.87%，四舍五入到整数就变成了 100），随后
  要求「可以用两位小数」。所以 99.87% 显示 `99.87%`、62% 显示 `62.00%`，
  只有**恰好满命中**才读 `100%`；
- **速度**按结算输出 token 除以宿主记录的模型耗时计算，计入首包等待和重试，截止在工具执行前。

纵轴刻度**只走 50 的倍数**（用户 2026-11-13 要求「每 50 一个可读」）：
峰值 ≤50 就是 `0/50`，108 就是 `0/50/100/150`；速度上千时才放大成
`0/500/1000/…`（仍是 50 的倍数，否则 92px 高的绘图区画不下）。

## 数据从哪来

每个会话独立统计。支持原始会话事件的 DSH（已核对 0.2.2-rc.1）直接从
`sessions.binding(sessionId).eventSource` 读取当前会话的新增正文和思考，使用宿主的时间戳。
插件复用 DSH 已打开的会话连接。重连快照、加载旧消息和结算节点不进入实时速度。

旧版 DSH 回退到 `useChat(snapshot => snapshot.legacy.partial)`。首次挂载和切换会话只建基线，
连续观测到新步骤时计入首包。同一步中的累计文本按采样区间分摊，隐藏窗口恢复后重建基线。

实时速度只计正文和思考。纯工具参数通常集中在接近步骤结束的一批到达，参数用量记入每步表格。

两个槽位用 `slots.inject(name, cb)` 等待宿主声明后注册，声明重建时自动重新注册。

## 为什么是「估算」

流式 chunk 里**只有字符**，没有 token 数 —— 真实 token 数要等这一轮流结束、
宿主给出 `usage` 才有。所以实时速度只能换算：

```
tokens ≈ CJK字符 × 1.0 + 其它字符 ÷ 4.2
```

这两个系数不是拍脑袋的：用本机真实数据回归得出（25 个会话 / 19415 条回复 /
69,248,359 字符 → 13,780,630 outputTokens = **5.03 字符/token**，其中 CJK 占 3.1%）。
业界主流做法也是启发式估算（[token-metrics](https://socket.dev/npm/package/token-metrics)、
[Qwen 的 estimate_token_counter](https://github.com/rayrayraykk/CoPaw/blob/86fda39f95d5557b60952c85c1a25923e9c8f918/src/qwenpaw/agents/utils/estimate_token_counter.py)）。

**代码密集时会偏高，纯中文时会偏低** —— 它反映的是趋势，不是账单。

## 平滑口径

正文和思考的估算 token 按原始时间戳进入两级各 650ms 的指数平滑。同毫秒增量直接累加。
有可靠时间区间的快照增量在区间内均匀分摊。迟到的增量根据已有时序影响当前读数，历史点保留原值。

收到有效增量后，胶囊约每 100ms 读取一次。两级滤波状态都低于 0.5 tok/s 后停止刷新。

## 两个页签的取数

**实时速度**与胶囊使用同一组读数。折线每秒保留一个峰值，并使用该峰值的实际时刻。
「当前」是最近一次胶囊读数，「平均」是所选时间内包含空闲的时间加权平均。
历史保留 5 分钟，可切换 1 / 3 / 5 分钟。

**每步输出**：不是折线，是**一张表**。token 用量取宿主助手节点上的 `usage`
（`inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens`），真实账单；
「读取」= `cacheReadTokens`，「输入」= `inputTokens`（**未缓存**那部分，不是
`total − output` —— 那会把缓存算进来），「命中」= 读取 ÷（读取 + 输入 + 写入）。
部分字段缺失时，宿主给出的总用量与输出用量也可确定输入总量；仍无法确定时命中率显示 `—`。
结算后的「速度」= `outputTokens ÷ ((completedTime − stepStartTime) / 1000)`。
这段时间包含首包等待和重试，截止于模型回复完成。输出用量或有效时长缺失时显示 `—`。
流式期间按当前快照的累计正文和思考估算输出，速度等结算后计算。结算行随宿主快照更新，
按轮次和步号倒序，加载旧消息时仍显示最近的步骤。

曲线是**平滑的**（单调三次 Hermite 转贝塞尔）：转折处不再是直角台阶，同时
**保形不过冲** —— 数据里的峰值就是曲线的峰值，不会被样条再画大一次。

## 样式

- 胶囊：逐条照抄宿主 `StatsPills` 的 `.anchor` / `.pill` 规则（字号走
  `--dsh-content-font-size-secondary` 变量，不写死），仪表图标用宿主 `gauge-outline`
  的几何（`viewBox 0 0 16 16`、`stroke-width 1`）。数字占**固定 4ch 宽、右对齐**，
  速度变化时胶囊外框不跟着抖（否则会把右边官方胶囊一起推来推去）。
- 弹层：**不透明**的 `--dsw-alias-bg-base`（浅色主题 = 白）+ 宿主
  `--dsw-elevation-prominent` 阴影，字体与胶囊同源。不用 `--dsw-alias-bg-overlay` ——
  那是半透明色，叠在聊天内容上会发灰。折线与文字统一用 `--dsw-alias-label-tertiary`
  （就是官方 `.pill` 那一条 `color:`）。

## 安装

```bash
pnpm install
pnpm build
```

装进 profile：

```bash
# 让插件管理器按本地目录安装（会写 profile 的 package.json 与 bundles 列表）
# 或手工在 profile 的 package.json 里加：
"dsh-token-tps-stats": "file:<本仓库的绝对路径>"
```

**改完 `src/` 必须重新 `pnpm build`**：profile 链接的是本目录，宿主读的是 `lib/client.js`。

## 加载速度

客户端产物是**压缩过的**（`tsdown` 的 `minify: true`）：源码里那些设计说明不会被搬进
`.js`。同一版代码：

| | 未压缩 | 压缩后 |
| --- | --- | --- |
| `lib/client.js` | 108.9 KB（源码合计） | **24.0 KB** |
| gzip | — | **8.4 KB** |

（`lib/client.js` 从 16.3 KB 涨到 24.0 KB 是因为加了「每步输出」那张表 + 步账 +
页签：功能多了，产物自然会大。压缩仍在生效 —— 同样这批源码不压缩是 100 KB 量级。）

另外两点也省启动开销：

- 没有声明 `dsh.client.immediately`，宿主**按需物化**这个包（第一次 `require` 才执行
  工厂），不抢启动阶段的跑道；
- 胶囊归零后停止刷新。实时折线打开时每 500ms 推进时间轴，每步表格随数据和滚动刷新。

## 运行时开销

速度计只保留两级滤波状态，增量和读数都以常数时间计算。历史最多保留最近 5 分钟的读数，
面板打开时按需整理为每秒峰值。结算表读取时才解析近期步骤，同一份宿主快照复用已解析的行。

[旧版算法对比](docs/tps-algorithm-comparison.md)保留了固定窗口与自适应分母的历史测试。

## 门槛

- Node ≥ 22.19.0
- DSH ≥ 0.2.0-rc.2

## 它**不**做什么

- 不读账号、不读额度、不碰任何厂商配置 —— 它只跟「当前会话正在流出多少字」有关；
- 不发任何网络请求；
- 不改任何既有插件的行为。注册失败时只打一行 `console.error`，失败半径只有这一个胶囊。
