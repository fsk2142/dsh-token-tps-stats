# dsh-token-tps-stats

在 DSH 输入框底部那一行显示**当前会话的实时输出速度**（tok/s），排在那两个官方胶囊
（轮次/步数、用量）的左边。**点一下胶囊**，会在它正上方弹出图表，左上角可以切换
**实时速度**（最近 1 / 3 / 5 分钟）与**每步输出**（最近 5 / 10 / 20 步）。

## 它长什么样

```
◷ 实时输出速度（TPS）：42 tok/s   ◷ 93 轮 4047 步 · 148 tok/s   ⛁ 1159M tok · …
```

- 模型在流式输出时数字**持续跳动**（一律整数：小数位来自换算系数的猜测，不是真精度）；
- 速度**缓升缓降**：真实速度突然变快时，指针要 ≈3 秒才走完 63%、≈9 秒到 95%
  （一阶低通，τ = 3s）；
- 停下来后同样**慢慢降**（τ = 3s），不是啪一下归零；
- 完全没有动作时**固定在 `0 tok/s`**（不会消失）。

点胶囊会弹出图表（`shell.overlay` 槽位，`position: fixed` 摆在胶囊正上方，
上方放不下就摆到下方）。**左上角两个页签**切换整张图：

```
┌────────────────────────────────────────┐
│ [实时速度] [每步平均]                × │
│ 实时速度 · 最近 1 分钟                 │
│ 当前 42 tok/s · 平均 31 · 峰值 58      │
│ 100 ┤                                  │
│     │        ╭─╮                       │
│  50 ┼───╭───╯ ╰──╮──────────           │
│     │   ╯         ╰                    │
│   0 ┴──────────────────────────────    │
│   60 秒前                        现在  │
│                    [1 分钟][3 分钟][5 分钟]│
└────────────────────────────────────────┘
```

切到「每步」，**不再画折线**，而是一张表（用户 2026-11-13：「直接列出来第一步，
输出多少，输入多少，命中多少，平均速率多少」）：

```
┌────────────────────────────────────────────────────┐
│ [实时速度] [每步输出]                            × │
│ 每步输出 · 最近 5 步                               │
│ 读取/输入/输出是宿主的真实用量；命中 = 读取 ÷ 提示总量…│
│ 步     读取    输入   输出  命中   速度             │
│ #2.3  364,213   1,204   812   100%  47 tok/s        │
│ #2.2  363,530     988   153   100%  38 tok/s        │
│ #2.1  363,092     721   640   100%  52 tok/s        │
│                         [5 步][10 步][20 步]        │
└────────────────────────────────────────────────────┘
```

列的**顺序与简称**是用户定的：「缓存读取、未缓存输入、输出、缓存命中、平均速度，
但是都用简写：读取 / 输入 / 输出 / 命中 / 速度」。

- **读取** = `cacheReadTokens`；**输入** = `inputTokens`（**未缓存**那部分，
  不是 `total − output` —— 那会把缓存算进来）；**输出** = `outputTokens`；
- **命中** = 读取 ÷（读取 + 输入 + 写入）。**整数位会进位到 100 时多留一位小数**
  （用户 2026-11-13 问「为什么命中率都是 100%」—— 那一行真实是 99.87%，四舍五入
  到整数就变成了 100）。所以 99.87% 显示 `99.9%`，只有**恰好满命中**才读 `100%`；
- **速度**：优先用我们观察到的「有字在流」时长；没观察到就退回宿主节点的
  同步 `timing`（`completedTime − firstTokenTime`，即真正在生成的那一段，
  不含等工具返回）。两者都没有就显示 `—`，**不拿墙钟凑数**。

纵轴刻度**只走 50 的倍数**（用户 2026-11-13 要求「每 50 一个可读」）：
峰值 ≤50 就是 `0/50`，108 就是 `0/50/100/150`；速度上千时才放大成
`0/500/1000/…`（仍是 50 的倍数，否则 92px 高的绘图区画不下）。

## 数据从哪来

**每个会话各自统计**：胶囊挂在 `conversation.composer.dock`（`scope: "session"`），
从槽位标准属性里读**当前这个会话**的聊天快照 —— `useChat(snapshot => snapshot.legacy.partial)`
给出的正是「这一步正在生成的文本」，官方那两个胶囊（轮次/步数、用量）读的是同一份快照。

两个槽位都用 `slots.inject(name, cb)` **等声明**再注册，而不是拿到 `slots` 就立刻
`register`：槽位声明由声明方条目在自己生命周期里建立，窗口形态变化、条目重挂时还会
撤掉重建 —— 直接注册赌的是「激活这一刻声明已经在了」，重启后批次顺序一变就会报
`slot "…" is not declared (a parent entry's children table must declare it)`，
胶囊整个消失。`slots.inject` 会在声明提交后回调、在声明重建时再跑一次（先执行上次的清理）。

不再监听 `assistant/live-chunk`：那张事件注册表是**全局**的，每个会话都会把同一个
Definition 拿去匹配自己那份事件流 —— 累加器只能混成一锅（子代理同时跑时尤其离谱），
而且它的载荷里根本没有会话 id。（详见 `src/client/session-store.ts` 的说明。）

快照里的文本是**累计**的，所以每拍自己做差分，只把新增的部分计入；
新增的字按「两次采样之间的真实时间差」摊开（`spread.ts`），
避免主线程被占住后一次性出现的几秒文本把读数顶到上千。

统计 `text` 与 `reasoning` 两类块（思考也是模型真实产出的 token）；工具参数不算
（客户端快照里 `tool-call` 块的 `argsRaw` 在流式中途**始终是空串**，宿主只在
`block-end` 才填进去 —— 拿不到增量就没有速率可言）。

代价：本会话实测 725 条助手回复里 **374 条（52%）只有工具调用、没有可见文字**，
那些步骤的读数会是 0。所以胶囊分三种状态：

| 状态 | 显示 | 什么时候 |
| --- | --- | --- |
| 有速度 | `实时输出速度（TPS）：42 tok/s` | 正文/思考正在流 |
| 只调工具 | `实时输出速度（TPS）：工具调用中` | 有 `tool-call` 块、但参数还是空的（宿主还没填 = 还在生成） |
| 空闲 | `实时输出速度（TPS）：0 tok/s` | 两者都不是 |

「工具调用中」**复用数字那块定宽位置**，宽度与「4ch + ` tok/s`」几乎相等，
阶段切换时胶囊不会伸缩。它只换文字，**不进速度计** —— tok/s 的口径始终是
「输出文本的速度」。

## 为什么是「估算」

流式 chunk 里**只有字符**，没有 token 数 —— 真实 token 数要等这一轮流结束、
宿主给出 `usage` 才有。所以实时速度只能换算：

```
tokens ≈ CJK字符 × 1.0 + 其它字符 ÷ 4.2
```

这两个系数不是拍脑袋的：用本机真实数据回归得出（25 个会话 / 19415 条回复 /
69,248,359 字符 → 13,780,630 outputTokens = **5.03 字符/token**，其中 CJK 占 3.1%）。
业界主流做法也是启发式估算（[token-metrics](https://socket.dev/npm/package/token-metrics)、
[Qwen 的 estimate_token_counter](https://github.com/rayrayraykk/CoPaw/blob/86fda39f95d5557b60952c85c1a25923e9c8f918/src/qwenpaw/agents/utils/estimate_token_counter.py)）。

**代码密集时会偏高，纯中文时会偏低** —— 它反映的是趋势，不是账单。

## 平滑口径（两层 + 时间轴摊开）

```
会话快照 → 差分出新增文本 → 按采样时间差摊开 → 毫秒桶 → 最近 9 秒平均 → 3 秒低通 → 显示值
```

1. **时间轴摊开**（`spread.ts`）。快照按宿主自己的节奏发布（动画帧级），正常流式一格
   ≈ 16ms；但主线程被占住（后台标签页、渲染大表格）时会几十秒不发布，回来时那段文本
   一次性出现在增量里。不摊开的话那几十秒的字会记在同一毫秒上，最近 1 秒的窗口全吃进去
   —— 那就是读数冲到 1000 多的来源。现在按**两次采样之间的真实时间差**把字符摊回它
   真正跨越的区间。
2. **最近 9 秒的平均**（1 秒 × 9 窗口）。**分母固定 9、空窗口按 0 计入**。
3. **3 秒一阶低通**：瞬时速度很高，指针也要慢慢爬上去；下降同理。

停机超过 800ms 没有新帧 → 从**当前显示值**按 τ = 3s 指数衰减，低于 0.5 tok/s 归零。

## 两个页签的取数

**实时速度**：与胶囊**同一口径** —— 每秒一个桶，每个点 = 最近 9 秒的滑动平均
（分母同样固定 9）。时间轴只画**已走完的整秒**，最后一点最多晚 1 秒，但形状诚实
（不会每帧塌一个坑）。历史保留 5 分钟；可切 1 / 3 / 5 分钟。

**每步输出**：不是折线，是**一张表**。token 用量取宿主助手节点上的 `usage`
（`inputTokens` / `outputTokens` / `cacheReadTokens` / `cacheWriteTokens`），真实账单；
「读取」= `cacheReadTokens`，「输入」= `inputTokens`（**未缓存**那部分，不是
`total − output` —— 那会把缓存算进来），「命中」= 读取 ÷（读取 + 输入 + 写入）。
「速度」优先用我们观察到的「有字在流」时长（单次间隔封顶 2 秒、时长下限 500 毫秒，
所以**分母只可能偏大、读数只可能偏低**）；没观察到就退回宿主节点的 `timing`
（`completedTime − firstTokenTime`，真正在生成的那一段）；两者都没有才显示 `—`。

曲线是**平滑的**（单调三次 Hermite 转贝塞尔）：转折处不再是直角台阶，同时
**保形不过冲** —— 数据里的峰值就是曲线的峰值，不会被样条再画大一次。

## 样式

- 胶囊：逐条照抄宿主 `StatsPills` 的 `.anchor` / `.pill` 规则（字号走
  `--dsh-content-font-size-secondary` 变量，不写死），仪表图标用宿主 `gauge-outline`
  的几何（`viewBox 0 0 16 16`、`stroke-width 1`）。数字占**固定 4ch 宽、右对齐**，
  速度变化时胶囊外框不跟着抖（否则会把右边官方胶囊一起推来推去）。
- 弹层：**不透明**的 `--dsw-alias-bg-base`（浅色主题 = 白）+ 宿主
  `--dsw-elevation-prominent` 阴影，字体与胶囊同源。不用 `--dsw-alias-bg-overlay` ——
  那是半透明色，叠在聊天内容上会发灰。折线与文字统一用 `--dsw-alias-label-tertiary`
  （就是官方 `.pill` 那一条 `color:`）。

## 安装

```bash
pnpm install
pnpm build
```

装进 profile：

```bash
# 让插件管理器按本地目录安装（会写 profile 的 package.json 与 bundles 列表）
# 或手工在 profile 的 package.json 里加：
"dsh-token-tps-stats": "file:C:/Work/dsh-plug-in/dsh-token-tps-stats"
```

**改完 `src/` 必须重新 `pnpm build`**：profile 链接的是本目录，宿主读的是 `lib/client.js`。

## 加载速度

客户端产物是**压缩过的**（`tsdown` 的 `minify: true`）：源码里那些设计说明不会被搬进
`.js`。同一版代码：

| | 未压缩 | 压缩后 |
| --- | --- | --- |
| `lib/client.js` | 72.6 KB | **16.3 KB** |
| gzip | 26.2 KB | **6.5 KB** |

另外两点也省启动开销：

- 没有声明 `dsh.client.immediately`，宿主**按需物化**这个包（第一次 `require` 才执行
  工厂），不抢启动阶段的跑道；
- 运行时没有常驻定时器：胶囊在读数归零时停表，弹层只在打开时才有 500ms 的刷新定时器，
  帧缓冲只在有帧排队时才持有一次 `setTimeout`。

## 门槛

- Node ≥ 22.19.0
- DSH ≥ 0.2.0-rc.2

## 它**不**做什么

- 不读账号、不读额度、不碰任何厂商配置 —— 它只跟「当前会话正在流出多少字」有关；
- 不发任何网络请求；
- 不改任何既有插件的行为。注册失败时只打一行 `console.error`，失败半径只有这一个胶囊。

## 开发

```bash
pnpm typecheck   # tsc --noEmit
pnpm test        # vitest run
pnpm build       # tsdown
```

测试覆盖的是**纯计算**（`tps-meter` / `tps-history` / `chart-geometry` /
`chart-store` / `pacing` / `live-buffer`）：换算系数、9 窗口语义、3 秒缓冲、
时间轴重排、折线几何与保形平滑、弹层开关状态。

`tests/client/replay-regression.test.ts` 会把本机真实流式时间线（`.tmp/replay.json`，
不在版本库里）重放两遍：正常流式一遍、积压 flush 一遍；后者钉住「旧做法冲到
1000 多 / 新做法回到真实量级」这条回归。没有这个数据文件时整组自动跳过。

React 组件本身由宿主渲染，只做「读状态 → 出元素」。
